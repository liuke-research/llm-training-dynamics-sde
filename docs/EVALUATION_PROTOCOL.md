# 事件级评估协议

以 [evaluation.py](../src/llm_sde/evaluation.py) 与 [benchmark.py](../src/llm_sde/benchmark.py) 为准。

## 时间和匹配

预警窗口默认 40 个 optimizer step。对发生于 `onset` 的事件，仅 `onset - 40 <= alarm_step < onset` 的告警才算提前告警；发生当天步不算提前。每个事件选择最早的一个尚未匹配告警，每条提前告警最多匹配一个事件。

事后检测另算，默认窗口是从 `onset` 到 `min(onset + 10, end)`，含端点。提前命中与事后检测可能同时发生，不应把二者加起来称为精确率。

事件区间不能重叠，但相邻事件的预警窗口可能重叠；当前实现按发生时间依次贪心匹配，并非最大匹配求解器。多事件密集时应先约定合并规则。

## 指标分母

- 提前事件召回率：提前命中的事件数 / 已知事件总数。
- 严格提前告警精确率：成功匹配的提前告警数 / 所有告警数。事件发生后硬故障告警也进入分母。
- 健康记录误报率：健康且已暖启动的观测记录上的告警数 / 健康记录数 × 1000。
- 提前量：只对成功提前命中的事件计算 `onset - alarm_step`。

健康记录排除事件前 40 步到事件结束的区间。这里的分母是实际观测记录数，不是未被记录的训练步数。没有事件、没有告警或没有健康记录时，对应比率可能为 `null`，不强行改成 0 或 100%。

## 标签来源

合成场景有单独生成的标签；模型训练标签由固定 Loss excursion 规则从实际测量结果确定。两者只进入评估，不输入特征或监控器。

小模型标签默认使用此前 64 条 Loss 的中位数，在 Loss 同时超过 `center + 0.7` 与 `1.8 * center` 时标记候选，要求连续 2 条，并合并相隔不超过 20 步的区间。非有限值另有处理。这是本项目约定，不是行业统一的“训练失败”定义。

## 开发与留出

六类合成场景；开发 seeds 为 0–3，留出 seeds 为 100–107，每条 700 步。阈值搜索网格为 0.5、0.6、0.7、0.8、0.9；五种评分方法使用相同搜索协议、窗口及门控。

只在开发运行上选择阈值，并先写盘，再生成留出数据。置信区间按 seed 成组 bootstrap，保留同 seed 六场景之间的配对关系。每个方法的因子尺度为固定启发式设计，未系统搜索全部超参数。

## 必须保留的负结果

无前兆的突发 Loss 事件没有被提前预测；无害梯度/LR 变化可能误报。50× LR 干预未产生所定义的损失事件却告警，必须作为误报保留。5000× 压力测试用于检查失败路径，不是自然故障泛化评估。
